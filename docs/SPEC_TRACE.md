## Key deviations (intentional — see Cycle 16 audit)

1. **Auto clock-in is entry-triggered**, not "≤5 min before scheduled start".
   Employees arriving early are clocked in on geofence entry (mitigated by
   shift-end close + once-per-day guard). No-shift/company-default employees
   have no geofence → no auto clock-in path.
2. **Duplicate handling is BOTH preventive and corrective** (resolved from the
   Cycle 16 "preventive-only" state): `reclockGuard` still rejects most double
   punches, but proxy punches and out-of-order offline replays that slip through
   are now FLAGGED (`isFlaggedDuplicate`) and surfaced for one-tap Option A
   auto-merge rather than silently accepted. Cycle 17 widened BOTH windows from
   120 s to a 600 s dwell window after field reports of a second session while
   the employee never left the geofence (a ~3-minute GPS bounce cleared the old
   120 s guard AND flag).
3. **No-show grace is layered**: the Notification-Centre alert fires at 10 min
   (`noShowGrace`, configurable), while the cron `no_show` _status_ transition
   stays at 120 min (no clock-in recovery path exists).
4. **Multi-company access is master-only (Option A)**: there is no user↔company
   membership table — `User.companyProfileId` is a single scalar, and the only
   cross-tenant path is the `master` role's impersonation JWT-swap, reachable via
   the Master Console company register (the header `CompanySwitcher` dropdown was
   removed). Managers remain single-company. A true multi-company manager model
   (membership join table) is deferred as an ADR.
5. **Manager push covers only critical alerts**: the closed-app push
   (`pushManagerAttendanceAlerts`) notifies admins/managers of duplicate punches
   and no-shows only. Late clock-ins / early clock-outs / absences remain in-app
   (Notification Centre) to avoid push fatigue for informational events.
6. **Customer payroll templates + per-company headers are partial**: the export
   registry (`payrollExportFormats.ts`) now ships a ready-to-use component-row
   import format (`componentHoursFormat`: Basic Pay / Overtime @ 1.5 / Overtime
   @ Double Time, one row per employee per component) via `defineComponentFormat`.
   Per-company configurable headers remain deferred (needs migration 25).
